# Blender_breakdance

自分のブレイクダンス動画（`me.mp4`）と見本の動画（`OK.mp4`）から3D骨格を取り出し、姿勢のズレを数値化して、Blender 上で Mixamo Y-Bot 2体に動きを再現するツールです。

```
動画 ─①3D骨格化─▶ poses_*.json ─②差分解析─▶ report.txt / alignment.json ─③Blender再現─▶ breakdance_compare.blend
```

## 必要なもの

| 用途 | 内容 |
|---|---|
| Python 3.12 | `pip install opencv-python numpy` |
| PyTorch (GPU) | `pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128`（RTX 50 系は CUDA 12.8 版が必要） |
| NLF モデル | `models/nlf_l_multi_0.3.2.patch4.torchscript`（[isarandi/nlf](https://github.com/isarandi/nlf/releases) v0.3.2） |
| Y-Bot | `models/y_bot.fbx`（Adobe Mixamo からダウンロード。無ければスティック人形で代用） |
| Blender | 5.0（4.4 以降なら動く想定） |

## 使い方

```bash
python extract_poses.py        # ① OK.mp4 -> poses_expert.json, me.mp4 -> poses_my.json
python analyze_diff.py         # ② report.txt と alignment.json を出力
"/c/Program Files/Blender Foundation/Blender 5.0/blender.exe" -P apply_poses.py   # ③ Blender で開く
```

- `.blend` だけ作る場合: `blender -b -P apply_poses.py -- --save breakdance_compare.blend`
- 別の動画を使う場合: `python extract_poses.py 動画.mp4 出力.json`（自分 = `poses_my.json`、見本 = `poses_expert.json`）

## ファイル

| ファイル | 役割 |
|---|---|
| `extract_poses.py` | ① 動画から3D骨格を抽出（NLF） |
| `extract_poses_mediapipe.py` | 旧版（MediaPipe）。参考用 |
| `pose_features.py` | 姿勢の特徴量（関節角度など）の計算。②で使用 |
| `analyze_diff.py` | ② 自分と見本の対応付けとズレの解析 |

| `breakdance_compare.blend` | ③の出力 |

## アルゴリズムの解説

### ① 動画から3D骨格を取る（`extract_poses.py`）

1. **黒帯の除去**: 縦動画を横長で書き出した左右の黒帯を自動で見つけて切り取る。動画から約10枚のコマを取り、どれか1枚でも明るさが20を超える列・行を「映像がある部分」とみなす。
2. **3D骨格の推定**: 3D人体推定モデル NLF に16コマずつまとめて渡し、体の24関節（SMPL 形式）の、カメラから見た実際の3D位置（メートル、x右・y下・z奥）を得る。
   - 少しずつ回転させた5通りの画像で推定して平均し、結果を安定させる（`num_aug=5`）。
   - 人物検出は反転画像でも行い、逆さの人を見逃しにくくする。
   - 「ありえない姿勢」を自動で捨てる機能はオフ（逆さの姿勢まで捨てられるため）。
3. **本人の追跡**: 複数人が映っているときは「面積 ÷ (1 + 前コマの本人からの距離²)」が最大の人を選ぶ。背景に小さく映る人には移らない。

> 旧版の MediaPipe は「人が立っている」前提のモデルで、逆さの姿勢では足が下にある人だと誤認していた。画像を 0/90/180/270° 回転させて一番直立して見える向きを使う工夫も試したが、改善しきれなかったため NLF に切り替えた。

### ② 自分と見本のズレを数値化する（`pose_features.py`, `analyze_diff.py`）

**撮影角度に左右されにくい11個の指標**

座標をそのまま比べるとカメラの位置で値が変わるため、体の中の角度だけを使う。

- 体軸の傾き（腰→胸の線と真上との角度。0°=直立、180°=逆さ）
- 肩と腰のねじれ（肩のライン・腰のラインを体軸に垂直な面に映した角度）
- 左右の肘・膝の曲がり、腕の開き、股関節の角度、両脚の開き

**比べる範囲の決め方**

各コマで一番低い関節が手・手首なら「手で体を支えている」とみなし、その最初〜最後のコマを比べる範囲にする。入りの踏み込みなど、見本に無い動作は自動で除外される。

**タイミング合わせ（部分 DTW）**

比べる範囲を、見本の中のひと続きの場面と、順番を保ったまま1コマずつ対応させる。

- ズレの大きさ = 11個の角度の差の平均
- 自分の1コマに対して見本を 0〜2 コマ進められる = 0.5〜2倍の速さの違いを吸収。見本が止まる場合は 8° のペナルティ（同じコマへの張り付き防止）
- 左右を入れ替えた場合も試す（回る向きが逆でも比べられる）
- 見本の技区間ごと・反転あり/なしで試し、平均ズレが最小の組み合わせを採用

**レポートの内容（`report.txt`）**

- ズレ上位5箇所（0.2秒以上離して選ぶ）と、それぞれ差の大きい関節4つ＋言葉のアドバイス
- 腰の高さ = 床（一番低い関節）から腰までの高さ ÷ 胴の長さ
- 床に体が着いた瞬間（手足以外の関節が一番低いコマ）
- 比べた範囲全体での平均差

### ③ Blender で Y-Bot に動きを移す（`apply_poses.py`）

**床の推定**

- 立っているコマ（体軸が真上から20°以内）が10コマ以上あれば、その体軸を「真上」とする。
- 無ければ、各コマの一番低い点（床に着いている点）に平面を当てはめる。浮いている点を除きながら3回やり直し、点が一直線に並んで傾きが決まらない場合に備えて傾きは小さい方へ寄せる。35°以上傾いたら採用しない。
- 床の高さ = 各コマの一番低い点の高さの 20 パーセンタイル。

**Y-Bot への移し方（向きのリターゲット）**

関節の「位置」に合わせると、手足の長さの違いで骨が変な方向に曲がる。そこで各部位の「向き」を写す。

1. Y-Bot を本人の脚の長さに合わせて拡大縮小する。
2. 腰→背骨→腕・脚の順（親から子）に、「親が動いた後の今の向き」から「動画の向き」への最小回転を求める。一から回し直さないので、ねじれが暴れにくい。
3. 腰と胸は、背骨の向きに加えて左右の股関節・肩を結ぶ線も使って体の正面を決める。
4. 求めた回転をキーフレームとして書き込む（FK なので Blender 上で手で修正できる）。

**その他**

- 見本は `alignment.json` の対応付けで並べ替え、自分と同じタイミングで動かす。
- 腰の軌跡（赤=自分、青=見本）、2体の自動配置、床とカメラ、ズレ上位5箇所のタイムラインマーカー（#1〜#5）を作る。

## 限界

- カメラ1台なので、奥行き方向の精度は左右・上下より低い。
- 腰の高さは「一番低い関節が床」という前提の目安。
- 顔の向き・指は取れていないので再現されない。
- 見本との対応付けは形が一番近い場面を機械的に選んでいるだけなので、技として同じ場面かは目で確認する必要がある。

## 注意（日本語パス）

MediaPipe と PyTorch は、日本語を含むパスの文字列を渡すとファイルを開けない。スクリプトではモデルをバイト列やファイルオブジェクトで渡して回避している。
